# KV 缓存：为什么首字延迟会变低

## 一句话结论

KV 缓存把已经算过的注意力键值存起来，下一个 token 不必重算整段上下文，所以缓存命中率越高，首字延迟越低。

## 它解决什么问题

- **重复计算**：没有缓存时，每生成一个 token 都要把前面所有 token 重新过一遍注意力。
- **长上下文**：上下文越长，重算越贵；缓存让每一步的成本只和新 token 有关。
- **多轮对话**：同一段系统提示在多次请求之间可以复用，前缀缓存命中后直接跳过预填充。

## 一个例子

| 场景 | 预填充 token | 命中缓存 | 首字延迟 |
|---|---:|---:|---:|
| 冷启动 | 8,000 | 0 | 1.9 s |
| 同一前缀第二次 | 8,000 | 7,600 | 0.3 s |

## 代价

缓存占显存：每个 token 的键值大小约等于 `2 × 层数 × 隐藏维度 × 字节数`。显存不够时只能换出或者缩短上下文。
