# 信任金字塔：让 agent 稳定产出好代码的方法

**一句话结论**
先把检查写进代码库和 CI（持续集成：每次提交自动跑检查），再让 agent 加速；顺序反过来，只会更快地产出返工。

## 方法：倒过来的金字塔

**核心观点**
工程师的工作从"写代码"变成"让错误的代码写不进来"。

**金字塔的五层**

越靠上越便宜，优先投入：

1. **代码库**：好的接口设计和清晰的目录结构
2. **静态检查**：lint 规则（静态检查规则：代码一写错就自动报错）、类型和测试

这两层是确定性的，agent 绕不过去。

3. **运行时验证**：让程序真的跑起来，用 Playwright（自动操作浏览器的测试工具）截图
4. **文字规则**：只放需要判断的事情
5. **人工审查**：最贵的一层

## 证据

- **合并量**：团队每月约 11,000 个 PR（代码合并请求）
- **回滚率**：约 0.5%，只统计被撤回的合并
- **发布节奏**：每天稳定发布

| 指标 | 7 月 | 11 月 | 变化 |
|---|---|---|---|
| lint 规则数 | 7 | 167 | +160 |
| 代码注释 | 65,824 | 1,227 | -98% |
| 每日发布 | ❌ 否 | ✅ 是 | 稳定 |
| 超时问题 | ⚠️ 183 处 | 12 | 修复中 |

> 注意：这些数字来自演讲者自己的团队，没有第三方核实。

## 我们怎么用

**先做的三件事**

1. **加 CI**：每次推送自动跑检查
2. **写草稿检查脚本**：中文交付前先过一遍
3. **做功能地图**：每个功能都有截图证明

```bash
npm run verify && npm run e2e
```
